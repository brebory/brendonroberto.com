Fiber’s first month

November 18, 2025

A month ago, my friend Stephen Cassidy and I started a game under the name Snackpack Games. It’s called Fiber, and right now it looks nothing like what we have in mind. That’s on purpose.

The pitch, from the README

The first commit landed on October 16. The README pitched a 2D platformer for squads of four, with paper and collage art. You’d craft gear and skills from materials you find, open gates with keys you crafted, and work through dungeons room by room, with a random encounter in each room. Towns would act as guild hubs, and the folk you rescue could move in and offer buffs and recipes. Power would come from crafting more than from leveling: less grinding for experience, more grinding for materials.

None of that exists yet. What exists is a character who can run and jump.

Start from something that runs

The project literally started as Godot’s official 2D tutorial, “Dodge the Creeps”, and the README admitted it still had a lot of tutorial files lying around. That was a fine place to begin: a working main scene, a player, enemies on a timer and a score. From there we swapped the top-down dodger for a side-on platformer, and Stephen pulled in Kenney’s free platformer art as placeholder and organized it. Kenney’s packs are the reason prototypes like this can look friendly on day one.

A player built from states

The player runs on a finite state machine: idle, running, jumping, falling, and a drop state for one-way platforms. Hold down on a platform and you drop through it, which turns a flat test map into something you can actually move around in. Each state owns its own input and physics, so adding a new move means adding a state instead of growing one giant _physics_process.

The first round of tuning was all feel: gravity, run speed and jump impulse, a collision shape that lines up with the sprite, and a sprite that flips when you change direction. Enemies that drift offscreen for five seconds despawn, so the test map doesn’t fill up with stragglers.

Tests from week two

I added GUT, the Godot unit testing tool, in the second week, and GitHub Actions runs the suite on every pull request with JUnit reports right in the PR. It feels early for a game that’s mostly a pink blob and some coins, but the habit is much easier to start now than to retrofit later, and everything after this gets built on top of it.

Maps that connect

The rest of the month was about having more than one place to be. Stephen built the town and the atlas, and I wired up the warps and started the inventory:

  • A first town map with a parallax background, so the sky scrolls behind the play space.
  • An atlas: a data model for which maps exist and how their edges and warps connect.
  • Warp events, so walking into a warp moves you to the matching spot on another map.
  • The start of an inventory: things you touch get picked up, and a dialog lists what you’re carrying.

Next up is giving the character something to be good at: stats, actions that cost stamina, and a reason to pick things up.

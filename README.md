brendonroberto.com
===

My personal website: a homepage, a blog of game development posts, and an art sketchbook.

The site is plain HTML, CSS and a little JavaScript. **There is no build step.** The repo root is deployed as-is, and everything in it is served exactly as written.

## Layout

| Path | What it is |
|---|---|
| `index.html` | The homepage |
| `404.html` | Shown for any URL that doesn't exist |
| `css/main.css` | Homepage styles |
| `css/post.css` | Shared blog post styles |
| `js/lightbox.js` | Click-to-enlarge for every image inside a `<figure>` |
| `blog/index.html` | The post list, newest first. This is the source of truth for the RSS feed and sitemap. |
| `blog/<slug>/index.html` | One folder per post, with its own `img/` and `video/` |
| `blog/feed.xml`, `sitemap.xml` | Generated by `scripts/build-feed.py` |
| `robots.txt` | Allows everything and points at the sitemap |
| `img/og/` | 1200×630 share images, one per page |
| `img/thumbs/` | 480×252 blog list thumbnails, made from each post's share image |
| `video/` | The homepage clip |
| `brendon-roberto-resume.pdf` | Resume, exported from the "(Website)" copy of the Google Doc, which leaves out phone, ZIP and email |
| `scripts/` | Maintenance scripts (below). These are served too, which is harmless. |

## Local preview

Vite is used only to serve the site locally with live reload:

```sh
npm install
npm run dev
```

## Scripts

All three need Python 3 (`python` on your PATH). `share-tags.py` also needs Pillow (`pip install pillow`). Each one has an npm alias: `npm run feed`, `npm run share-tags` and `npm run check`.

| Script | When to run it |
|---|---|
| `python scripts/build-feed.py` | After adding a post or changing its title, date or summary in `blog/index.html`. Rewrites `blog/feed.xml` and `sitemap.xml`. |
| `python scripts/share-tags.py` | After adding a page. Adds Open Graph and Twitter tags, a canonical URL and an RSS link to any page without them, and makes its share image in `img/og/` from its first image or video poster, or a title card if it has neither. It also makes any missing blog list thumbnail in `img/thumbs/`. Pages that already have tags are otherwise left alone. |
| `python scripts/check-links.py` | Before committing. Checks every local link, image, video and share image against the files on disk, and lists unused files and pages without share tags. Vite's dev server answers 200 for missing pages, so an HTTP check isn't enough. |

## Adding a blog post

1. Copy an existing post folder to `blog/<slug>/`. Each post links `/css/normalize.css` and `/css/post.css`, keeps its own styles in a `<style>` block, and loads `/js/lightbox.js` before `</body>`.
2. Set the `<title>` (`Post Title · Brendon Roberto`), the meta description and the `<time datetime="YYYY-MM-DD">` byline.
3. Add the post to the top of the list in `blog/index.html`, in date order: copy an existing `<div class="entry">` and point its thumbnail at `/img/thumbs/<slug>.webp`.
4. Run `npm run share-tags`, then `npm run feed`, then `npm run check`.

## Media conventions

- **Images:** at most 1600 px on the long side, WebP at quality 82–85 (Pillow works well). Give every `<img>` its `width`, `height`, `alt` and `loading="lazy"`.
- **Pixel art:** keep the original PNG or GIF and add `class="pixel"`, which scales it up without smoothing. The lightbox keeps it crisp too.
- **Video:** H.264 MP4 with no audio and `+faststart`, at most 1280 px wide. Use `<video controls muted playsinline preload="metadata" poster="...">`. For example:

  ```sh
  ffmpeg -i in.mp4 -an -vf "scale='min(1280,iw)':-2" -c:v libx264 -preset slow -crf 26 -pix_fmt yuv420p -movflags +faststart out.mp4
  ```

- **Generated art** is always labeled as generated, never presented as hand-drawn.
- In `<pre>` blocks, escape `<` as `&lt;`.

## Deploying

The site is hosted on Cloudflare Pages, connected to this repo:

- **Production branch:** `main`
- **Build command:** none
- **Build output directory:** `/` (the repo root)

Every push to `main` deploys, and every pull request gets a preview URL. `404.html` must stay in the root. Without it, Cloudflare Pages treats the site as a single-page app and serves the homepage for every unknown URL.

Share previews use absolute `https://brendonroberto.com/...` URLs, so they only work on the live domain. After changing a share image, refresh the cached preview with a tool like LinkedIn's Post Inspector.

Cloudflare Pages limits each file to 25 MB. Keep videos well under that.
